Deploy Agent em Novos Endpoints
Agent
Use Case
Cliente solicita instalação do agent em 50 novos notebooks adquiridos para o departamento financeiro.
Contexto
Ambiente Windows 11, domínio corporativo, endpoints na rede interna. Prazo: 2 dias úteis.
Sintoma Observado
Novos endpoints não aparecem no console EC após tentativa de deploy via script manual. Status mostra "unknown username or password" ou "connection timeout".
Causa Técnica
Firewall bloqueando portas 8020/8383, credenciais incorretas, DNS resolution issues, Admin$\temp não acessível, agent package incompatível.
Verificação Rápida (N1)
  1. Verificar se endpoints aparecem em Admin > Agent > Agent Deployment Status
  2. Checar se servidor EC está acessível: ping EC_SERVER
  3. Testar conectividade das portas: Test-NetConnection EC_SERVER -Port 8020
  4. Validar credenciais de domínio no console
Ações N2/N3
  1. Download agent package mais recente via Agent > Settings > Download Agent
  2. Criar target group com os 50 novos endpoints
  3. Executar deploy via Agent > Install Agent > Select Computers
  4. Monitorar deployment status em Agent > Deployment Status
  5. Para falhas: usar Agent Troubleshooting Tool no cliente
  6. Verificar logs: UEMS_CentralServer\logs\serverOut.txt
  7. Testar manual installation em endpoint piloto
Script para Cliente
Por favor, execute o Agent Troubleshooting Tool no seu computador (localizado em ManageEngine\UEMS_Agent\bin\agent_troubleshooting_tool.exe) e envie o relatório gerado. Caso necessário, baixe o agente manual aqui: [fornecer link do console] e execute como administrador.

Comandos para verificação (Executar como Admin):
1. Verificar conectividade: Test-NetConnection EC_SERVER -Port 8020
2. Verificar espaço em disco: dir C:
3. Verificar serviço: sc query UEMSAgent
4. Testar DNS: nslookup EC_SERVER
5. Verificar firewall: netsh advfirewall show allprofiles

Agent Communication Failure
Agent
Use Case
Cliente reporta que 15 endpoints estão offline no console, mas usuários confirmam que máquinas estão ligadas e na rede.
Contexto
Endpoints em home office, VPN corporativa, mix Windows 10/11. Issue iniciado após atualização de firewall.
Sintoma Observado
Console mostra status "Last Communication: 3 days ago". Agent Troubleshooting Tool mostra "Communication Failed" e "Server not reachable".
Causa Técnica
Porta 8020/8383 bloqueada no firewall/VPN, agent service parado, configuração de proxy alterada, DNS resolution falhando, certificado SSL expirado.
Verificação Rápida (N1)
  1. Checar status do agent no console: Admin > Agent > Agent Status
  2. Verificar último heartbeat timestamp
  3. Pingar servidor EC do endpoint afetado
  4. Verificar se agent service está rodando: services.msc
Ações N2/N3
  1. Executar Agent Troubleshooting Tool no endpoint cliente
  2. Testar conectividade: Test-NetConnection EC_SERVER -Port 8020,8383
  3. Verificar server logs: UEMS_CentralServer\logs\serverOut.txt
  4. Reiniciar agent: Restart-Service UEMSAgent
  5. Verificar logs do agent: C:\Program Files (x86)\ManageEngine\DesktopCentral_Server\agent\logs
  6. Configurar regras de firewall para liberar portas 8020/8383
  7. Se persistir: reinstall agent via script silencioso
Script para Cliente
Por favor, execute o Agent Troubleshooting Tool no seu computador (localizado em ManageEngine\UEMS_Agent\bin\agent_troubleshooting_tool.exe) e envie o relatório gerado. Caso necessário, baixe o agente manual aqui: [fornecer link do console] e execute como administrador.

Comandos para Verificação (Executar como Admin):
1. Verificar serviço: sc query UEMSAgent
2. Reiniciar serviço: net stop UEMSAgent && net start UEMSAgent
3. Testar comunicação: "C:\Program Files (x86)\ManageEngine\DesktopCentral_Server\agent\bin\agent.exe" -ping
4. Forçar comunicação: "C:\Program Files (x86)\ManageEngine\DesktopCentral_Server\agent\bin\agent.exe" -forceCommunication
5. Verificar conectividade: Test-NetConnection EC_SERVER -Port 8020,8383
6. Verificar logs: dir "C:\Program Files (x86)\ManageEngine\DesktopCentral_Server\agent\logs"

Agent Upgrade Schedule
Agent
Use Case
Cliente precisa atualizar 200 endpoints da versão 10.0.123 para 10.1.2131 para suportar novos recursos de MDM.
Contexto
Ambiente production, janela de manutenção das 22:00-02:00, mix desktop/laptop, usuários remotos.
Sintoma Observado
Alguns endpoints falham upgrade com error "Agent service could not be stopped". Upgrade History mostra status "Failed" e "Retry Scheduled".
Causa Técnica
Processos bloqueando upgrade (aplicações abertas), permissões insuficientes, espaço em disco inadequado, versão incompatível, Windows Update em execução.
Verificação Rápida (N1)
  1. Verificar versão atual dos agents: Admin > Agent > Agent Status
  2. Checar espaço em disco dos endpoints afetados
  3. Verificar se há upgrades pendentes no console
  4. Identificar padrões de falha (horários, tipos de máquina)
Ações N2/N3
  1. Download agent upgrade package 10.1.2131 via Admin > Agent > Settings
  2. Criar maintenance window schedule: Admin > Agent > Upgrade Agent
  3. Segmentar upgrade em batches de 50 endpoints
  4. Configurar retry policy: 3 tentativas com 10min interval
  5. Para endpoints com falha: forçar stop do agent antes do upgrade
  6. Monitorar upgrade status em Admin > Agent Settings > Upgrade History
  7. Configurar notificações de email para falhas
  8. Gerar relatório pós-upgrade com sucesso/falha
Script para Cliente
Por favor, execute o Agent Troubleshooting Tool no seu computador (localizado em ManageEngine\UEMS_Agent\bin\agent_troubleshooting_tool.exe) e envie o relatório gerado. Caso necessário, baixe o agente manual aqui: [fornecer link do console] e execute como administrador.

Upgrade Manual (Executar como Admin):
1. Feche todas as aplicações abertas
2. Verifique espaço em disco: dir C:
3. Baixe o upgrade: [Link para upgrade package]
4. Execute: msiexec /i DCAgentUpgrade.msi /qn REBOOT=ReallySuppress
5. Aguarde conclusão (verifique serviço UEMSAgent)
6. Reinicie máquina se necessário
7. Confirme versão no console com suporte

Software Deployment

Deploy Microsoft Office 2021
Software
Use Case
Cliente solicita instalação do Microsoft Office 2021 em 120 endpoints substituindo Office 2019.
Contexto
Licença volume licensing, ambiente Windows 10/11, necessidade de preservar configurações de usuário.
Sintoma Observado
Deploy falha em endpoints com Office 2019 instalado com erro "Another installation is in progress". Deployment Status mostra "Failed" e "Error Code: 1618".
Causa Técnica
Conflito de instalação, Office 2019 não desinstalado corretamente, Windows Installer corrompido, dependências ausentes, permissões insuficientes.
Verificação Rápida (N1)
  1. Verificar deployment status: Software > Software Deployment > Deployment Status
  2. Checar se Office 2019 aparece em Software Inventory
  3. Identificar padrões de falha (tipos de máquina, horários)
  4. Verificar espaço em disco dos endpoints afetados
Ações N2/N3
  1. Criar Configuration Profile com uninstall do Office 2019
  2. Preparar Office 2021 deployment package com Office Deployment Toolkit
  3. Configurar dependency: uninstall Office 2019 primeiro
  4. Criar installation script com parâmetros silent: /configure configuration.xml
  5. Testar deployment em 5 endpoints piloto
  6. Configurar deployment schedule fora do horário comercial
  7. Monitorar deployment status em Software > Deployment Status
  8. Para falhas: verificar logs em C:\Windows\Logs\Software
  9. Validar instalação via inventory scan
Script para Cliente
Execute o comando abaixo no Prompt de Comando como Administrador e informe o resultado ou erro exibido:

1. Feche todas as aplicações Office
2. Verifique espaço em disco: dir C:
3. Desinstale Office 2019 via Painel de Controle
4. Execute: msiexec /i pacote.msi /qn
5. Aguarde instalação completa (pode levar 30+ minutos)
6. Abra Word/Excel para ativação automática
7. Se erro "Unable to deploy the software", contate suporte

  3. Configurar silent installation: msiexec /i AcroRdrDC.msi /qn ALLUSERS=1 EULA_ACCEPT=YES
  4. Criar Configuration Profile para desativar auto-updates
  5. Configurar installation parameters para suprimir reboot
  6. Testar deployment em endpoints com diferentes versões
  7. Executar deployment em batches de 50 endpoints
  8. Para falhas: verificar logs em %temp%\Adobe Reader logs
  9. Validar instalação via Software Inventory
Script para Cliente

Patch Management

Critical Windows Security Patches
Patch
Use Case
Cliente precisa aplicar patches críticos da Microsoft (Zero-day) em 500 endpoints dentro de 24 horas.
Contexto
Vulnerabilidade crítica CVE-2024-XXXX, ambiente production, janela de manutenção limitada.
Sintoma Observado
Alguns endpoints falham patch installation com error "Windows Update service not running". Patch Status mostra "Failed" e Attention Required section lista múltiplas falhas.
Causa Técnica
Windows Update service desabilitado, disco cheio, conflito com WSUS local, permissões insuficientes, rede bloqueada, endpoints desligados.
Verificação Rápida (N1)
  1. Verificar Patch Status: Patch Management > Patch Status
  2. Checar Attention Required section para falhas críticas
  3. Identificar endpoints offline ou com falhas
  4. Verificar espaço em disco dos endpoints afetados
Ações N2/N3
  1. Download dos patches críticos via Microsoft Update Catalog
  2. Criar Patch Policy com prioridade "Critical"
  3. Configurar auto-approval para critical patches
  4. Definir deployment schedule imediato
  5. Testar em 10 endpoints piloto
  6. Executar deployment em batches de 100 endpoints
  7. Para falhas: usar Manual Deployment via Patch Management > Manual Deployment
  8. Configurar retry policy: 3 tentativas com intervalo de 1 hora
  9. Monitorar Patch Status em Patch Management > Patch Status
  10. Gerar compliance report pós-deployment
Script para Cliente
Verifique o espaço em disco (C:) e feche aplicações desnecessários. Aguarde a instalação automática ou informe se aparecer algum erro.

Comandos para Verificação (Executar como Admin):
1. Rodar Patch Scan manual
2. Verificar espaço em disco: dir C:
3. Verificar Windows Update service: sc query wuauserv
4. Iniciar serviço se parado: net start wuauserv
5. Checar seção "Attention Required" no console
6. Se erro "Low Disk Space", liberar espaço em disco

  3. Adicionar colunas: Department, OU, Patch Status, Last Scan Time

  5. Definir threshold para compliance (95%)
  6. Exportar relatório em formato CSV/Excel
  7. Criar dashboard customizado no Analytics Plus

Remote Access

Remote Support Session
Remote
Use Case
Usuário em home office precisa de suporte remoto para resolver problema de aplicação crítica.
Contexto
Usuário conectado via VPN, bandwidth limitado, necessidade de acesso rápido para resolver issue de produção.
Sintoma Observado
Remote Control falha com error "Connection timeout" ou "Black screen". Remote Control session logs mostram "Gateway connection failed" e "User permission denied".
Causa Técnica
Gateway portas bloqueadas (8031, 8443), VPN bandwidth limitado, configuração de video incompatível, user confirmation desativado, firewall bloqueando.
Verificação Rápida (N1)
  1. Verificar Remote Control status: Remote Control > Remote Control Status
  2. Checar Gateway status: Admin > Remote Control > Gateway Settings
  3. Testar conectividade básica com endpoint
  4. Verificar se usuário está online no console
Ações N2/N3
  1. Verificar Gateway status e portas (8031, 8443)
  2. Testar conectividade com endpoint: ping/traceroute
  3. Configurar Remote Control settings para low bandwidth
  4. Desativar features: Wallpaper, Aero, Mirror Driver
  5. Habilitar User Confirmation se necessário
  6. Configurar multi-monitor support
  7. Iniciar sessão remota com permissão do usuário
  8. Documentar sessão no Service Desk ticket
  9. Coletar logs: RemoteControl.log se houver falha
Script para Cliente
Permita o acesso remoto quando solicitado na tela. Caso veja tela preta, feche e tente novamente.

Comandos para Verificação (Executar como Admin):
1. Testar telnet
2. Verificar se Remote Control Gateway está rodando
3. Verificar firewall permite porta 8443
4. Verificar serviço: sc query UEMSAgent
5. Reiniciar serviço: net stop UEMSAgent && net start UEMSAgent
6. Se erro "The specified service does not exist", instalar Remote Control component

  6. Configurar user enrollment vs device enrollment

Mobile Device Compliance
MDM
Use Case
Cliente precisa configurar políticas de compliance para dispositivos móveis e gerar relatórios.
Contexto
Requisitos de segurança corporativa, necessidade de bloquear dispositivos não-compliant.
Sintoma Observado
Dispositivos mostram como "non-compliant" mesmo atendendo todos os requisitos. MDM > Compliance mostra "Evaluation Failed" e "Policy not applied".
Causa Técnica
Policy evaluation delay, settings não sincronizados, versão do MDM client desatualizada, conflito de políticas, rede instável.
Verificação Rápida (N1)
  1. Verificar Compliance Status: MDM > Compliance
  2. Checar se dispositivos estão online
  3. Validar políticas configuradas
  4. Forçar sync manual em dispositivo piloto
Ações N2/N3
  1. Configurar Compliance Policy requirements
  2. Definir actions para non-compliant devices
  3. Configurar evaluation schedule (a cada 4 horas)
  4. Criar regras específicas por tipo de dispositivo
  5. Testar compliance evaluation em dispositivos piloto
  6. Monitorar compliance status em MDM > Compliance
  7. Gerar compliance reports mensais
  8. Configurar alertas para dispositivos non-compliant
  9. Documentar procedimentos de remediation
  10. Revisar políticas trimestralmente
